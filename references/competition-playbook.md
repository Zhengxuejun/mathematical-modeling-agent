# 国赛/美赛数学建模作战手册 / Competition Playbook

本文件用于真实比赛或课程大作业的执行编排。目标不是“写得像建模”，而是稳定产出：可运行代码、可信结果、清晰论文、可复盘归档。

## 1. 总体节奏

### 72 小时比赛建议

```text
0–3h：读题、选题、数据初查、风险评估
3–8h：确定总体方案、子任务 DAG、分工、目录结构
8–24h：数据清洗、基线模型、第一版结果
24–40h：核心模型迭代、图表、敏感性分析
40–56h：论文主体成稿、结果复核、附录整理
56–66h：摘要、排版、图表编号、交叉检查
66–72h：最终检查、导出 PDF/DOCX、备份、提交
```

### 24 小时课程/校赛压缩版

```text
0–2h：读题、拆问、确定模型路线
2–8h：数据处理、基线模型、关键图表
8–14h：核心模型求解、敏感性分析
14–20h：报告成稿
20–24h：排版、检查、导出、归档
```

## 2. 选题风险评估

读完所有题后，用 5 个维度快速打分，每项 1–5 分：

| 维度 | 高分含义 |
|---|---|
| 数据可用性 | 数据完整、字段清晰、可直接处理 |
| 模型可控性 | 能明确转为优化/预测/评价/仿真问题 |
| 结果可验证 | 有基线、指标、现实常识或测试集验证 |
| 写作空间 | 有足够图表、解释、策略建议 |
| 风险 | 低依赖冷门库、低依赖不确定外部资料 |

优先选择：数据明确 + 模型可控 + 结果可验证的题。不要被“看起来高级”的题吸引。

## 3. 第一小时读题清单

必须输出：

1. 每问要求的最终交付物。
2. 所有数据文件/字段/单位/时间范围。
3. 题目显式约束和隐含约束。
4. 可以直接回答的问题与需要建模的问题。
5. 可能的模型候选。
6. 最大风险点：数据缺失、模型不可解、题意歧义、结果难验证。

## 4. 子任务 DAG 模板

```text
T0 题目解析与数据审计
 ├─ T1 数据清洗与特征构造
 │   ├─ T2 描述统计与可视化
 │   └─ T3 参数估计/指标权重
 ├─ T4 问题一模型与求解
 │   └─ T5 问题一结果解释
 ├─ T6 问题二模型与求解（依赖 T1/T3/T4）
 │   └─ T7 问题二结果解释
 ├─ T8 敏感性/鲁棒性分析（依赖 T4/T6）
 └─ T9 论文整合与附录归档
```

每个任务都要有：输入、输出、负责人/执行者、完成判据、文件路径。

## 5. 最小可交付版本 MVP

比赛中先做 MVP，再升级模型。

### MVP 必须包含

- 数据能读入并清洗。
- 每问有一个基线模型。
- 每问有至少一个结果表或图。
- 有一份可读报告草稿。
- 有基本敏感性/误差分析。

### 升级方向

- 单目标 → 多目标。
- 静态模型 → 动态/情景模型。
- 手工权重 → 熵权/AHP/组合赋权。
- 简单预测 → 加入特征工程/模型对比。
- 单一结果 → 鲁棒性/敏感性/不确定性分布。

## 6. 数据工作规范

### 原始数据保护

- `data/raw/` 只放原始文件，不手改。
- `data/processed/` 放清洗后的中间数据。
- 每次清洗输出日志：行数、列数、缺失、异常、删除/填补数量。

### 数据审计输出

`results/tables/data_audit.csv` 至少包含：

| 字段 | 类型 | 缺失数 | 缺失率 | 唯一值数 | 最小值 | 最大值 | 备注 |
|---|---|---:|---:|---:|---:|---:|---|

### 单位统一

单位转换必须在代码和报告中同时说明。常见坑：吨/千克、公里/米、小时/分钟、万元/元、百分比/小数。

## 7. 代码工作规范

推荐结构：

```text
src/
  00_data_audit.py
  01_preprocess.py
  02_baseline.py
  03_model_q1.py
  04_model_q2.py
  05_sensitivity.py
  06_make_figures.py
  utils.py
```

要求：

- 每个脚本可单独运行。
- 输出路径固定写入 `results/`。
- 不把绝对路径写死到代码中。
- 随机模型固定 `RANDOM_SEED = 42`。
- 关键结果保存为 CSV/JSON/PNG，同时在终端打印摘要。

## 8. 图表优先级

高价值图表：

1. 数据分布图：直方图、箱线图。
2. 趋势图：时间序列折线。
3. 空间/区域图：地图或分组柱状。
4. 模型结果图：最优方案、路径、排序、预测曲线。
5. 敏感性图：参数扰动对目标函数/排序的影响。
6. 对比图：基线 vs 改进模型。

低价值图表：无标题饼图、无解释相关热力图、与结论无关的花哨图。

## 9. 论文写作分工逻辑

论文不是最后才开始。建议同步写：

- 读题后先写：问题重述、问题分析、初版假设。
- 数据清洗后写：数据来源、预处理、描述统计。
- 模型确定后写：变量、公式、求解方法。
- 结果出来后写：结果分析、敏感性、优缺点。
- 最后写：摘要、关键词、终稿结论。

摘要最后写，但摘要的“结果槽位”一开始就预留。

## 10. 交叉检查清单

### 公式-代码一致性

- 公式中的每个变量是否在代码中有对应列/数组？
- 代码中的目标函数是否等于论文公式？
- 约束方向 `<= >= =` 是否一致？
- 单位是否统一？

### 图表-正文一致性

- 正文是否引用每个图表？
- 图表编号是否连续？
- 图题是否准确？
- 图表中的数值是否来自最新结果？

### 结论-题目一致性

- 每个小问是否有明确答案？
- 是否直接给出排序/方案/数值/建议？
- 是否避免“可能、一定程度、较好”等模糊词堆砌？

## 13. 失败预案

### 模型跑不出结果

- 降级到基线模型。
- 缩小规模抽样验证。
- 使用启发式或贪心解。
- 把不可解原因写成模型限制，但必须给替代结果。

### 数据质量差

- 明确缺失与异常处理。
- 做情景分析而非假装精确。
- 给置信区间或结果范围。

### 时间不够

优先级：

```text
明确回答题目 > 代码可运行 > 图表清楚 > 敏感性分析 > 模型高级 > 排版精美
```
