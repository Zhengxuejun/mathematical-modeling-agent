# 报告一致性检查清单 / Report Consistency Checklist

本文件用于终稿前检查：题目、模型、代码、图表、摘要、附件是否一致。它是建模论文最后 10% 质量提升的核心工具。

## 1. 使用时机

在以下阶段必须使用：

1. 报告初稿完成后；
2. 每次重新运行核心模型后；
3. 生成 DOCX/PDF 前；
4. 最终提交包打包前。

## 2. 题目-结论一致性

| 检查项 | 通过标准 |
|---|---|
| 每个小问都有独立回答 | 问题 1/2/3... 结尾均有明确数值、方案、排序、判断或建议 |
| 输出形式符合题面 | 题面要求 result.xlsx、路径表、分组区间、检测时点等均已生成 |
| 没有遗漏显式约束 | 容量、时间窗、阈值、速度范围、样本条件等均被处理 |
| 没有回答非题所问 | 模型介绍不替代题目答案 |

## 3. 公式-代码一致性

| 检查项 | 通过标准 |
|---|---|
| 变量一致 | 论文变量表中的变量都能在代码/数据中找到对应 |
| 目标函数一致 | 代码优化目标与论文公式同向、同量纲 |
| 约束一致 | `<=`、`>=`、`=` 方向无误，边界值一致 |
| 参数一致 | 成本、速度、阈值、权重、时间段等不前后冲突 |
| 单位一致 | 代码和论文中的 kg/吨、m/km、周/天、比例/% 已统一 |

## 4. 数据-结果一致性

| 检查项 | 通过标准 |
|---|---|
| 原始数据只读 | 没有直接修改原始附件 |
| 审计结果被引用 | 行数、样本量、缺失率、异常处理与数据审计一致 |
| 处理日志完整 | 删除、填补、筛选、合并都有记录 |
| 结果可追溯 | 每个关键数值能追溯到结果表或运行日志 |
| 随机结果可复现 | 随机种子和运行参数已记录 |

## 5. 图表-正文一致性

| 检查项 | 通过标准 |
|---|---|
| 图表编号连续 | 图 1、图 2... 表 1、表 2... 不跳号不重复 |
| 正文引用完整 | 每张图/表在正文中都有引用和解释 |
| 图题准确 | 图题描述变量、对象、时间范围、单位 |
| 数值最新 | 图表来自最新运行结果，不是旧版本 |
| 格式清晰 | 坐标轴、单位、图例、中文字体可读 |

## 6. 摘要-正文一致性

摘要最后写，并逐项核对：

| 摘要内容 | 核对来源 |
|---|---|
| 方法名称 | 模型章节标题和公式 |
| 样本量/数据范围 | 数据审计表 |
| 核心结果数值 | 最终结果表 |
| 优化提升比例 | baseline 对照表 |
| 结论建议 | 各问结果分析章节 |

禁止摘要出现正文没有支撑的“显著提升、准确率很高、效果良好”。

## 7. 附件/提交文件一致性

如果题目要求提交结果文件：

- [ ] result.xlsx 文件存在；
- [ ] 列名和模板一致；
- [ ] 行数符合题目对象数量；
- [ ] result.xlsx 数值与论文表格一致；
- [ ] 支撑代码能重新生成 result.xlsx；
- [ ] README_submit.md 写明运行入口。

## 8. 课程报告/DOCX 特别检查

适用于用户课程实验/报告：

- [ ] 标题下方是否有用户要求的学院/班级/姓名信息；
- [ ] 基础实验和扩展实验是否分开记录；
- [ ] 每个实验是否有目标、步骤、结果、截图/输出；
- [ ] 截图是否放在对应章节正文内；
- [ ] 图号是否连续；
- [ ] 平台截图与下载 txt 不一致时，是否以平台截图可见结果为准并说明。
