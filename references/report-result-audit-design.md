# 报告-结果自动一致性检查增强设计

本文件沉淀本轮 `mathematical-modeling-agent` 优化后的下一阶段执行方向：把报告一致性检查从人工 checklist 升级为可运行的自动审计器。

## 触发场景

当用户要求：

- “继续优化数学建模智能体”；
- “检查报告有没有和结果对上”；
- “提交前再核一遍图表/数值/附件”；
- “把建模报告低级错误自动查出来”；

应优先考虑实现或运行报告-结果一致性审计。

## 核心目标

自动交叉核对：

```text
报告正文 / 摘要 / 公式 / 图表引用
↔ 03_结果表格/
↔ 04_图表/
↔ 02_代码/运行日志
↔ 07_提交包/
```

目标不是替代人工审稿，而是提前发现最容易毁掉建模报告的低级错：旧图、旧表、摘要数值错、图号不连续、结果文件没进提交包、正文声称的指标在表格里找不到。

## 最低审计项

| 审计项 | 自动化方式 | 风险等级 |
|---|---|---|
| 报告文件存在 | 查 `05_报告定稿/*.pdf/*.docx/*.md/*.tex` | 高 |
| 图表文件存在 | 查 `04_图表/*` | 中 |
| 结果表格存在 | 查 `03_结果表格/*.{csv,xlsx,json}` | 高 |
| 图号/表号引用 | Markdown/LaTeX 可 regex；DOCX 用 python-docx | 中 |
| 图表文件是否被引用 | 文件名、图号、caption 粗匹配 | 中 |
| 摘要关键数值 | regex 抽取百分数/小数/整数，和结果表近似匹配 | 高 |
| 单位一致 | 抽取 kg/吨/km/周/% 等单位，检查同一指标混用 | 高 |
| 代码入口存在 | 检查 `--entry` 指向脚本 | 中 |
| 提交包 manifest | 检查 `submission_manifest.json`、`SHA256SUMS.txt` | 高 |

## 推荐脚本形态

未来可新增：

```text
scripts/audit_report_consistency.py
```

建议接口：

```bash
python audit_report_consistency.py /path/to/project \
  --report 05_报告定稿/report.md \
  --strict
```

输出：

```text
06_过程记录/一致性检查/auto_report_audit.json
06_过程记录/一致性检查/auto_report_audit.md
```

## 实现优先级

### P0：Markdown/LaTeX 支持

最容易稳定实现：

- 读取 `.md/.tex` 文本；
- regex 抽取 `图1`、`图 1`、`Figure 1`；
- regex 抽取 `表1`、`Table 1`；
- 抽取百分数与小数；
- 与 `03_结果表格/*.csv` 中的数字做近似匹配；
- 输出 warning/fail。

### P1：DOCX 支持

使用 `python-docx`：

- 抽取段落文本；
- 抽取表格文本；
- 检查图表题注；
- 检查正文图表引用。

### P2：PDF 支持

PDF 文本抽取依赖环境差异较大，只作为可选增强。优先检查源 Markdown/DOCX/LaTeX。

## 判定口径

| 状态 | 含义 |
|---|---|
| pass | 明确存在且匹配 |
| warn | 缺失但不一定致命，或无法自动判断 |
| fail | 明确缺失、路径不存在、关键数值找不到、提交文件不完整 |

严格模式下：

```text
fail 或 warn 均返回非零
```

普通模式下：

```text
只有 fail 返回非零
```

## 注意事项

- 自动审计只检查一致性，不评价模型是否正确。
- 不要把“数字能匹配”误判为“结论正确”。
- DOCX/PDF 抽取失败不能永久记成工具不可用，只能作为当次环境限制处理。
- 对于截图型图表，除非另有 OCR/视觉工具，否则只检查文件存在与正文引用。
- 若用户要求正式提交，自动审计通过后仍应人工快速通读摘要、每问结论和模型假设。
