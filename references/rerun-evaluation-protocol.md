# 复跑驱动的技能自检协议 / Rerun Evaluation Protocol

本文件用于把历史建模题“复跑”转化为对 `mathematical-modeling-agent` 的能力检查，而不是追求复现旧答案。复跑的核心目标是发现技能缺陷、补齐流程门禁、优化下一次真实建模任务的执行质量。

## 1. 复跑目的

复跑不是为了证明旧论文正确，也不是为了强行得到更优数值；复跑用于检查智能体是否具备以下能力：

1. **材料定位能力**：能否找到题面、附件、旧代码、旧报告、历史结论与缺失文件。
2. **题意重建能力**：能否从题面重新抽取任务、约束、变量、目标函数和交付物。
3. **数据审计能力**：能否先审计附件完整性、字段、单位、缺失、异常，而不是直接运行代码。
4. **模型选择能力**：能否判断旧模型是否匹配题意，是否存在口径偏差或隐含假设。
5. **代码复现能力**：能否在隔离目录运行旧代码，并记录必要改动。
6. **差异诊断能力**：复跑结果与旧结果不一致时，能否定位原因，而不是粉饰为“更优”。
7. **报告一致性能力**：能否检查题面、代码、图表、报告之间的指标、单位、口径是否一致。
8. **技能改进能力**：能否把发现的问题转化为可复用规则、模板、脚本或门禁。

## 2. 复跑前必须声明的问题

复跑开始前先回答四个问题：

```text
A. 本次复跑目标是什么？
   - 技能能力诊断 / 正式结果复现 / 论文重写 / 代码重构 / 模型升级

B. 复跑成功标准是什么？
   - 找到流程缺陷并更新技能
   - 或完整复现旧结果
   - 或生成新报告

C. 哪些文件是权威输入？
   - 原题面、原附件、旧代码、旧论文、历史技能记录

D. 哪些操作不得做？
   - 不污染原始数据目录
   - 不把合成数据冒充原始附件
   - 不把临时复跑数值写成正式结论
```

若用户的目的是“检查并优化技能”，则最终产物应优先是：

- 技能缺陷清单；
- 流程补丁；
- 新增门禁/模板/脚本；
- 对既有 reference 的修订；
- 而不是一份看似完整的旧题答案。

## 3. 复跑标准流程

### Step 0：加载相关技能

- 先加载 `mathematical-modeling-agent`。
- 按题型加载领域技能，例如 VRP 题加载 `vrp-solver`。
- 如果技能名变更或吸收合并，应先用 `skills_list` 查真实名称，不要依赖旧记忆中的名称。

### Step 1：建立复跑工作区

在 `~/Documents/数学建模/` 下创建隔离目录：

```text
<题名>_技能复跑_<YYYYMMDD_HHMMSS>/
  00_inputs_manifest/
  01_raw_copy/
  02_workspace/
  03_run_logs/
  04_diagnostics/
  05_skill_patches/
```

要求：

- 原始题面和附件只读复制，不直接修改。
- 旧代码复制到工作区后再改路径。
- 所有临时合成/重构数据必须显式标注 `synthetic` 或 `reconstructed`。

### Step 2：输入清单与缺失审计

输出 `inputs_manifest.md`：

```text
文件名 | 来源路径 | 是否存在 | 角色 | 权威性 | 问题
```

审计重点：

- 题面列出的附件是否齐全。
- 旧代码实际读取的文件是否齐全。
- 旧报告引用的数据是否能追溯到附件或代码输出。
- 历史技能记录是否与当前文件事实冲突。

### Step 3：题意与模型口径重建

输出 `problem_reconstruction.md`：

- 每个小问的目标函数/评价指标；
- 关键约束；
- 变量和参数；
- 数据字段映射；
- 争议口径或歧义点；
- 旧方案采用的口径；
- 当前复跑采用的口径。

如果发现口径歧义，必须列出多个候选解释及其影响。例如：

```text
绿色区圆心：题面文字可能为市中心(0,0)，旧代码/报告可能使用配送中心(20,20)。
影响：绿色区客户集合、EV/FV约束、成本结果、论文结论均会变化。
```

### Step 4：代码运行与最小修改记录

输出 `run_log.md`：

```text
运行命令：
环境：
修改文件：
修改内容：
修改原因：
是否影响模型逻辑：
输出文件：
```

原则：

- 先原样运行，记录失败。
- 只做最小必要修改，例如路径替换、依赖兼容。
- 不在未说明的情况下改模型逻辑。
- 若必须合成缺失数据，只能用于链路测试，并标注不能代表正式结果。

### Step 5：结果差异诊断

输出 `diagnostics.md`，区分四类差异：

| 差异类型 | 含义 | 处理方式 |
|---|---|---|
| 输入差异 | 附件缺失、数据版本不同、字段变化 | 标注不可正式复现 |
| 口径差异 | 题意解释、单位、圆心、时段等不同 | 列多口径结果或回到题面裁决 |
| 代码差异 | 路径、依赖、随机种子、bug 修复 | 记录 diff 与影响 |
| 模型差异 | 算法、目标函数、约束、参数变化 | 不能直接与旧结果比较 |

禁止把因输入缺失/口径改变导致的数值差异称为“模型优化”。

### Step 6：技能缺陷提取

复跑结束时必须回答：

```text
本技能在本题中暴露了什么缺陷？
- 触发/加载问题：
- 文件/附件审计问题：
- 题意重建问题：
- 模型库匹配问题：
- 代码执行问题：
- 报告生成问题：
- 质量门禁问题：
```

每个缺陷要转化为至少一种技能更新：

- 修改 `SKILL.md` 原则或工作流；
- 新增 reference；
- 新增 template；
- 新增 script；
- 修订领域技能；
- 写入 case study。

## 4. 输出模板

### 4.1 技能复跑诊断摘要

```text
# 技能复跑诊断摘要

## 本次复跑目标
用于检查并优化 mathematical-modeling-agent，而非正式复现旧答案。

## 关键发现
1. ...
2. ...

## 暴露的技能缺陷
| 缺陷 | 证据 | 已采取优化 |
|---|---|---|

## 对下次建模任务的改进
1. ...
2. ...

## 不应写入正式结论的内容
- ...
```

### 4.2 复跑质量门禁

完成前检查：

- [ ] 已明确复跑目标是“技能诊断”还是“正式复现”。
- [ ] 已建立隔离工作区，没有污染原始数据。
- [ ] 已输出输入清单并标注缺失文件。
- [ ] 已重建题意、目标、约束、变量、口径。
- [ ] 已记录原样运行失败/成功情况。
- [ ] 已记录所有代码和数据改动。
- [ ] 已解释新旧结果差异的来源。
- [ ] 已把发现的问题转化为技能更新。
- [ ] 最终回复优先汇报技能优化，而不是复跑数值。

## 5. 华中杯绿色物流 VRP 复跑暴露的技能改进点

该案例说明，数学建模智能体在“复跑历史题”时容易出现目标错位：用户要检查技能，但助手可能过度关注数值结果。因此新增以下规则：

1. **目标澄清前置**：历史题复跑必须先判定目的：技能诊断、结果复现、论文重写还是模型升级。
2. **附件完整性优先于结果**：发现 `时间窗.xlsx` 等关键附件缺失时，应把缺失本身作为技能诊断发现，而不是继续强调重构时间窗下的成本。
3. **案例记录重心调整**：case study 应记录“智能体哪里做得不够好、如何修技能”，而非只记录复跑数值。
4. **领域技能名称查验**：`green-logistics-vrp` 已被吸收到 `vrp-solver`，加载失败后应立即用 `skills_list` 查真实技能名。
5. **数值输出降权**：若输入非原始完整数据，复跑数值只能作为链路测试，不应作为主结论。

## 6. 维护规则

每次复跑历史建模题后，必须至少更新一个技能资产：

- 若发现流程缺陷：更新本文件或 `SKILL.md`。
- 若发现领域模型细节：更新相应领域技能，如 `vrp-solver`。
- 若形成可复用脚本：写入 `scripts/`。
- 若形成典型案例：写入 `references/case-study-*.md`。

没有形成技能资产的复跑，视为没有完成“技能优化”目标。
