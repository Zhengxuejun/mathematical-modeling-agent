## 2. 使用规则

1. **按题型加载**：先根据用户任务识别题型，再读取对应案例。
2. **按失败模式加载**：如果任务出现类似风险，例如附件缺失、重复测量、数据泄漏，也应读取对应案例。
3. **案例不是答案库**：案例用于提醒流程和门禁，不得把旧案例数值直接迁移到新题。
4. **案例要反哺技能**：每次真实任务后，若发现新失败模式，应更新本索引或新增案例。

## 3. 案例抽象层级

优先沉淀 class-level 经验，而不是会话流水账：

- 好：`重复测量数据不能默认独立，主体级划分训练/测试。`
- 差：`某次运行第 3 行报错，改了某个路径。`

## 4. 新案例命名规范

```text
references/case-study-<赛事或领域>-<年份或主题>-<短名>.md
```

示例：

```text
case-study-cumcm-2025-c-nipt.md
case-study-mcm-tourism-sustainability.md
case-study-vrp-time-window-missing-attachment.md
```

## 5. 新案例最低内容

每个案例至少包含：

1. 题目来源与本地材料路径；
2. 题型标签；
3. 数据/附件审计发现；
4. 正确建模路线；
5. 暴露的技能缺陷；
6. 已做的技能补丁；
7. 禁忌做法；
8. 下次遇到同类题的加载建议。
